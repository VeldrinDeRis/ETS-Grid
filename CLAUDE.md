## Журнал решений
Все решения фиксируются в [DECISIONS.md](DECISIONS.md) **в момент принятия**: новая запись `D-0NN` (дата, кто решил, что, почему), открытые вопросы — в таблицу «Ждут решения». Старые записи не переписываются — только «заменено D-0XX». После записи — коммит. Ниже краткая выжимка; при расхождении прав журнал.

`ets-grid-site/DECISIONS.md` (требование инструкции 02) — допущения по самому сайту для заказчика; общий журнал проекта — корневой.

## Гипотезы (D-028)
Продуктовые и бизнес-предположения — в [HYPOTHESES.md](HYPOTHESES.md), записи `H-0NN`: гипотеза, источник (обязателен), решения, проверка, критерий, статус, точки пересборки. Записывать в момент, когда на гипотезе строится решение или блок, до кода. Спецификация перечисляет свои гипотезы в шапке. Записи не переписываются — результат проверки в «Журнал».

## Порядок работы: спецификация → утверждение → тесты → код (D-022, D-023)
1. Модуль описывается в `specs/SPEC-0NN-*.md` по [шаблону](specs/_TEMPLATE.md): ссылки на ТЗ + контракт, состояния, «Мокап → боевой», критерии `AC-NN`. ТЗ не пересказывать, боевой контур не выдумывать.
2. Утверждение: фундамент, каталог, карточка, подборщики, корзина, главная — Дмитрий; SEO, контентные и служебные страницы — Claude сам, с записью в DECISIONS. Коммит `SPEC-0NN approved`.
3. Тесты: для логики — до кода, для интерфейса — вместе с кодом. В названии теста `SPEC-0NN/AC-NN`; индекс — `ets-grid-site/tests/README.md`. Баг → сначала воспроизводящий тест.
4. Код только по утверждённой спецификации; коммиты `SPEC-0NN: …`. Меняется поведение — сначала ревизия спецификации.
5. «Готово» — все `AC` отмечены и все тесты зелёные. Параллельные модули — в отдельных git worktree; в `main` сливаются только при зелёном `npm run test:all`. Пороги: unit/data — каждый коммит; build/functional/a11y — слияние; visual — отчёт до утверждения дизайна, потом слияние (D-024).
6. SPEC-001 «Фундамент» — первым и последовательно; остальные модули можно вести параллельно.
7. **Код — только по явной команде Дмитрия на конкретный модуль (D-032).** Утверждение спецификации не разрешает код. Незавершённый код — в ветке `wip/…`, не в `main`.

## Принятые решения (выжимка, 14.10.2026)
- **Прототип в коде, не в Figma.** Figma — позже, через `figma:*` скиллы после авторизации коннектора.
- **Стек:** кликабельный мокап, статическая сборка Astro 7 + TypeScript + чистый CSS-токены (без Tailwind); интерактив — острова Preact 10; данные — JSON-коллекции; показ — локально и zip со `start.cmd` (D-019). Анимация — ванильный `motion` (`animate`, `inView`), не `motion/react`. Каждая анимация уважает `prefers-reduced-motion`.
- **URL всех страниц — по `03_struktura_i_filtry.md`** (`/koshyk/`, `/oformlennya/`, `/dyakuyemo/`, `/porivnyannya/`, `/posluhy/…`), а не по именам файлов из §3 инструкции 02.
- **Первый экран — акцент на бизнес** (паркинг, отель, ТЦ: заработок на зарядке, Solar Carport, работа в блэкаут). Дом и АЗС — через плитки и вкладки ниже.
- **Материалов заказчика нет:** логотип, фото объектов, контакты, цифры — только видимые плейсхолдеры `[ТЕЛЕФОН]`, `[N об'єктів]`, `[ЦІНА]`. Ничего не выдумывать.
- **Ничего не скрывать (D-031):** чего не хватает — показываем на месте плейсхолдером или неактивным элементом с пометкой; блоки и элементы из-за отсутствия данных не прятать.
- **География:** «Київ і вся Україна».
- **Палитра:** направление А «Тёплый свет» (`#0D1424` / `#FFB547` / `#F4F6F8`), Б «Сигнал» — переключением токенов. Запрещено: лайм `#C8F03C`, Unbounded, JetBrains Mono.

## Инструменты
- Дизайн: `impeccable` (основной), `frontend-design`, `design:*` (critique, ux-copy, accessibility-review), `design-motion-principles`, `/motion`.
- Тексты: `marketing:draft-content` (крупные блоки), `design:ux-copy` (микротексты), `marketing:competitive-brief` (конкуренты → `research/`).
- Документация свежих версий (Astro 7, TS 6): MCP `context7` — сверяться перед кодом. Для Astro сначала `resolve-library-id` и проверить, есть ли у `/withastro/astro` версия 7.x в поле Versions; если нет (на 14.10.2026 там только 6.3.1) — брать `/withastro/docs` (D-021).
- MCP `context7` и `motion` продублированы в local-scope (`~/.claude.json`, только эта папка): приложение не подхватывает серверы только из проектного `.mcp.json`. `.mcp.json` оставлен как общий конфиг.
- Проверка: Playwright MCP, Chrome DevTools MCP (`lighthouse_audit`), встроенный браузер.
- Windows: PowerShell с `ExecutionPolicy RemoteSigned` (CurrentUser) — `npx`/`npm` работают.
