## 1. Жёсткие правила (нарушать нельзя)
1. **Первый экран продаёт.** H1 о результате, подзаголовок, ценовой якорь «від … ₴ з монтажем», основная CTA «Підібрати станцію», вторичная «Розрахувати під ключ», 4 плитки уровней, полоса доверия. На 375×667 основная CTA видна без прокрутки.
2. **4 уровня** (Зарядні станції · Сонячні панелі та СЕС · Батареї · Solar Carport) доступны из шапки на любой странице и плитками на главной.
3. **Фильтры** строго по разделу 9 ТЗ. Главный фильтр «Тип» показывается визуальными чипами над листингом. Есть счётчики, 0-значения неактивны, пустой выдачи нет, состояние хранится в URL.
4. **HTML с сервера.** Каталог, карточки, FAQ, характеристики должны быть видны без JS. Нельзя рендерить каталог только скриптом (это ошибка всех трёх референсов).
5. **Не перегружать.** 2 шрифта, 1 акцентный цвет, 1 основная CTA на экран. Без каруселей в герое, без скроллджекинга, без неона, без фонового видео. Яркость только в местах из таблицы 8.1 ТЗ.
6. **Запрещённая эстетика:** лайм `#C8F03C` на графите + Unbounded + JetBrains Mono как основа. Бери направление А «Тёплый свет» (по умолчанию) или Б «Сигнал» из раздела 8.2 и сделай переключение палитры одним набором CSS-токенов.
7. **Никаких выдуманных фактов.** Цены, количество объектов, годы, сертификаты, телефоны, отзывы, логотипы клиентов — только плейсхолдеры `[ЦІНА]`, `[N об'єктів]`, `[ТЕЛЕФОН]`. Демо-цены из `catalog-sample.json` помечены `"demo": true`, и на сайте рядом с ними стоит видимая метка «демо-ціна».
8. **Фото.** Можно использовать чужие фото станций, панелей, батарей, навесов (см. `04_FOTO_istochniki.md`). Каждое фото запиши в `public/img/CREDITS.md`: файл → источник URL → лицензия/статус. Кейсы «Об'єкти» не заполняй чужими фото как своими объектами: оставь блок с плашкой «Тут будуть реальні об'єкти ETS GRID».
9. **Язык интерфейса — украинский**, украинская типографика: «», —, ʼ, `кВт·год`, неразрывный пробел между числом и единицей.
10. **Подборщик мощности** учитывает «вхід від N кВт» станции (DC 60 требует от 65 кВт) и ёмкость батареи в кВт·год.
11. **Доступность:** видимый фокус, подписи полей, клавиатура, области касания ≥ 44 px, `prefers-reduced-motion`.

## 2. Стек
- **По умолчанию:** Astro (последняя стабильная) + TypeScript + CSS с токенами (без Tailwind-«вкуса по умолчанию», но Tailwind допустим, если токены вынесены). Интерактивы (фильтры, подборщики, корзина, сравнение, конфигуратор Carport) — острова Preact с `client:visible`.
- Данные: `src/data/catalog.json` (копия `data/catalog-sample.json`), коллекции Astro. CMS на этапе прототипа не нужна, но структуру держи совместимой с headless CMS.
- Корзина и сравнение хранятся в `localStorage` с try/catch. Оформление заказа — форма с валидацией, отправка в заглушку `POST /api/order` (логирует JSON). Оплату и Новую Почту не интегрируй, только UI-шаги с заглушками и пометкой `TODO: integration`.
- Без бэкенда на внешних сервисах и без ключей API. Никаких реальных платёжных данных.

## 4. План работы по шагам (с контрольными точками)
1. **Каркас:** проект, токены двух палитр, шрифты (2 семейства с поддержкой ґ/ʼ, Google Fonts или self-host), шапка с мега-меню, подвал, хлебные крошки. ✔ Сборка без ошибок.
2. **Главная:** все 11 блоков из раздела 6.1 ТЗ в указанном порядке. Сначала первый экран, его проверь на 1440×900 и 375×667 до перехода дальше. ✔ Скриншоты `qa/hero-1440.png`, `qa/hero-375.png`.
3. **Каталог и фильтры:** шаблон уровня, листинг, фильтры каждого уровня, URL-состояние, mobile bottom sheet. ✔ Ручная проверка: каждая комбинация главного фильтра даёт выдачу или корректный пустой экран с подбором.
4. **Карточка товара:** галерея, переключатель «Тільки обладнання / З монтажем», совместимость с авто, перекрёстные блоки, липкая панель на mobile.
5. **Подборщики** 4 уровней (≤ 3 вопроса, результат на том же экране) + «Чи вистачить потужності?» + конфигуратор Carport (формулы из `03_struktura_i_filtry.md`).
6. **Корзина → оформление → «Дякуємо»**, сравнение, поиск по названию/артикулу/разъёму.
7. **Сервисные страницы, пакеты, финансирование, контакты, 404.**
8. **SEO и разметка:** title/description, Schema.org `Product`/`Offer`/`BreadcrumbList`/`FAQPage`/`Organization`, sitemap, canonical для фильтров.
9. **QA** (раздел 6) и отчёт.

После каждого шага: собери проект, открой в браузере, исправь ошибки консоли, коротко допиши в `README.md` раздел «Прогрес».

## 5. Тексты
Пиши тексты сам на украинском по тону ТЗ (спокойный инженер, коротко, результат вместо характеристик). Без lorem ipsum. Пример тона:

## 8. Чего не делать
- Не менять структуру уровней и состав фильтров без записи в `DECISIONS.md` с обоснованием.
- Не подключать реальные платёжки, API Новой Почты, CRM, аналитику с реальными ID.
- Не вводить и не хранить пароли, ключи, реальные персональные данные.
- Не использовать 3D/WebGL/Spline в первом экране; не делать полноэкранный «шторочный» переход между уровнями (как в editorial-референсе). Уровни — это обычные страницы с URL.
- Не копировать вёрстку референсов целиком: это источник идей, а не шаблон.
