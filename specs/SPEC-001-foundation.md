## 1. Цель
Собрать основу, на которой модули SPEC-002…009 строятся параллельно и не конфликтуют. Это проект, данные, все адреса карты URL, общая раскладка страницы (шапка, мега-меню, подвал, хлебные крошки), контракт токенов с переключением палитры А/Б, общие мелкие компоненты, тестовая обвязка и сборка zip для показа. Каждый адрес сайта кликается с первого дня, даже если внутри пока заглушка.

### 3.2. Данные
- **`src/data/catalog.json`** — копия `brief/v1.0/data/catalog-sample.json` без изменения структуры (инструкция 02 §2). Коллекции Astro читают её через загрузчик `file()` с парсером, поле `id` берётся из `slug`. Получаются две коллекции: `products`, `systems`. Уровни берутся из `structure.json`, совпадение с `catalog.levels` проверяет AC-07 (ревизия 1).
- **`src/data/structure.json`** (новый) — источник навигации, которого нет в каталоге:
  - `levels[]`: `key`, `slug`, `name`, `short` (подпись плитки), `featured` (slug рекомендованного товара для мега-меню или `null`), `picker_href` (ссылка «Підібрати»);
  - `categories[]`: `level`, `slug`, `name`, `hint` (короткое уточнение из ТЗ §5, например «AC 3,7–22 кВт»). Входят все категории из 03 §1, в том числе те, где пока нет товаров;
  - `services[]`, `documents[]`: `slug`, `name`;
  - `contacts`: `phone`, `email`, `address`, `telegram`, `viber`, `requisites` — на старте только плейсхолдеры `[ТЕЛЕФОН]`, `[EMAIL]`, `[АДРЕСА]`, `[TELEGRAM]`, `[VIBER]`, `[РЕКВІЗИТИ]`.
- **Схема товара** (`src/content.config.ts`, Zod из `astro/zod`) по ТЗ §9.6 и образцу каталога:
  - обязательные: `slug`, `level` (1–4), `category`, `type`, `name`, `brand`, `country`, `attrs` (объект, ключи по уровню), `scenarios[]`, `sale_mode` (`cart` | `quote`), `price_equipment` (число | `null`), `price_turnkey_from` (число | `null`), `demo` (boolean), `stock` (`in_stock` | `preorder`), `delivery_days`, `warranty`, `images[]` (`src`, `alt`, `credit`), `cross_level[]`;
  - необязательные, по умолчанию `[]`: `docs[]`, `related[]` (есть в ТЗ §9.6, в образце отсутствуют);
  - **плейсхолдер** — строка вида `[…]` (`/^\[.+\]$/`). Он допустим везде, где заказчик ещё не дал значение, в том числе вместо числа (`battery_kwh: "[ЄМНІСТЬ]"`);
  - допустимые значения `type` и ключи `attrs` проверяет SPEC-002 по конфигу фильтров, фундамент принимает строку.
- **Запросы к каталогу** — только через `src/lib/catalog.ts`: `getLevels()`, `getCategories(levelKey)`, `getProductsBy({ level?, category? })`, `getProduct(slug)`, `getSystems()`, `getSystem(slug)`. Модули не читают JSON напрямую. Когда каталог переедет в CMS, меняется только загрузчик.

### 3.4. Шапка, мега-меню, мобильное меню, подвал, крошки
- **Шапка (desktop ≥ 960 px):** временный знак-словесный «ETS GRID» (ссылка на `/`) · 4 уровня из `structure.json` · поиск (форма `GET /poshuk/`, поле `q`) · `[ТЕЛЕФОН]` ссылкой `tel:` · кнопка «Розрахувати» (ведёт на форму расчёта, адрес задаёт SPEC-009) · корзина со счётчиком (ссылка на `/koshyk/`).
- **Мега-меню уровня:** название уровня — ссылка на страницу уровня, рядом отдельная кнопка-раскрывашка. Внутри: подкатегории с подсказкой `hint`, один рекомендованный товар (`featured`, если не `null`), ссылка «Підібрати» (`picker_href`). Иконки подкатегорий появятся с выбором набора иконок (раунд дизайна), до этого их место пустое.
- **Шапка (mobile < 960 px):** высота ≤ 64 px. Знак · корзина · кнопка «Меню». В открытом меню сначала 4 крупные плитки уровней, затем услуги, телефон и поиск (ТЗ §5: бургер не прячет уровни).
- **Подвал** (ТЗ §6.1): контакты-плейсхолдеры, карта уровней с категориями, услуги, документы, реквизиты `[РЕКВІЗИТИ]`, мессенджеры `[TELEGRAM]` `[VIBER]`, «Київ і вся Україна», переключатель палитры «А · Б» (только в мокапе, §3.6).
- **Хлебные крошки:** на всех страницах, кроме главной. Первая — «Головна» → `/`, последняя — текущая страница, без ссылки, с `aria-current="page"`. Товар: Головна › Уровень › Категория › Товар.
- **Скрипты шапки** — ванильный JS (Astro `<script>`), без Preact: мега-меню, мобильное меню, счётчик корзины. Preact грузится только на страницах с тяжёлыми островами (фильтры, подборщики, корзина).

### 3.6. Токены (`src/styles/tokens.css`)
Фундамент фиксирует **имена** токенов. Значения цветов палитр взяты из ТЗ §8.2, остальные значения временные и уточняются в раунде направления дизайна (impeccable, перед SPEC-006). Компоненты используют только токены, без «сырых» цветов и размеров.

- **Переключение палитры:** атрибут `data-palette="a" | "b"` на `<html>`. Меняется одним атрибутом. В мокапе переключатель в подвале сохраняет выбор в `localStorage` (`etsgrid:palette`), а встроенный скрипт в `<head>` применяет его до отрисовки, без мигания.
- **Поверхности:** `data-surface="day" | "night"` на секции переключает смысловые цвета внутри неё (ритм светлых и тёмных секций, ТЗ §8.1).
- **Цвета (смысловые):** `--color-bg`, `--color-surface`, `--color-ink`, `--color-ink-muted`, `--color-line`, `--color-accent`, `--color-on-accent`, `--color-focus`, `--color-status-ok` (в наявності, мережі вистачає), `--color-status-wait` (під замовлення), `--color-placeholder`.
- **Опорные значения:** А — ночь `#0D1424`, свет `#FFB547`, день `#F4F6F8`. Б — графит `#11110F`, бумага `#ECEBE4`, сигнал `#FF4D00`.
- **Шрифты:** `--font-display`, `--font-text`; цифры — `font-variant-numeric: tabular-nums` текстового шрифта (третье семейство не вводим). До раунда дизайна — системный стек, файлов шрифтов 0.
- **Размеры и ритм:** шкала шрифта `--step--1 … --step-5` (плавная, `clamp`), отступы `--space-3xs … --space-3xl`, `--section-y` (96–140 px на desktop, 56–80 px на mobile, ТЗ §8.1), `--container`, `--gutter`, `--header-h` (≤ 64 px на mobile), радиусы `--radius-s/m/l`, тени `--shadow-1/2`.
- **Движение:** `--dur-fast` 200 мс, `--dur` 320 мс, `--dur-slow` 600 мс, `--ease-out`, `--ease-spring`. При `prefers-reduced-motion: reduce` все длительности обнуляются глобально.
- **Брейкпоинты** (в медиазапросах, не переменные): 600, 960, 1280 px.
- **Запрещено** нигде в CSS: `#C8F03C`, Unbounded, JetBrains Mono.

### 3.7. Хранилище браузера и события
- `src/lib/storage.ts`: `read(key, fallback)`, `write(key, value)`, оба в try/catch. Недоступный `localStorage` или испорченный JSON → `fallback` без ошибки в консоли.
- **Ключи** (с версией, чтобы смена формата не ломала старые данные):

| Ключ | Владелец | Минимальная форма |
|---|---|---|
| `etsgrid:cart:v1` | SPEC-005 | `{ slug: string; qty: number; turnkey: boolean }[]` |
| `etsgrid:compare:v1` | SPEC-005 | `string[]` (slug, до 4) |
| `etsgrid:palette` | фундамент | `"a"` \| `"b"` |

- После изменения корзины модуль корзины посылает событие `etsgrid:cart-change` на `window`. Счётчик в шапке слушает его и событие `storage` (другие вкладки).
- `src/lib/track.ts`: `track(event, params?)` — в мокапе только `console.debug`. Имена событий — из ТЗ §10.4 (`hero_cta_click`, `level_tile_click`, `filter_apply`, `add_to_cart` …). Модули вызывают `track()` сразу, в боевом сайте меняется только реализация.

### 3.8. Форматирование (`src/lib/format.ts`)
- `formatNumber(n)` — `uk-UA`: группы разрядов через неразрывный пробел U+00A0, дробная часть через запятую.
- `formatPrice(n)` — `formatNumber` + U+00A0 + `₴`; `null` → `null`.
- `formatUnit(n, unit)` — число + U+00A0 + единица. Единицы пишутся строго: `кВт`, `кВт·год` (средняя точка U+00B7), `Вт`, `kWp`, `В`, `м²`, `год`.

## 4. Поведение и состояния
- **Без JS:** все ссылки шапки, подвала и крошек работают. Уровни в шапке — обычные ссылки на страницы уровней, раскрывашки не нужны. Мобильное меню открывается через `<details>`. Поиск отправляет форму. Счётчик корзины скрыт.
- **С JS:** мега-меню и мобильное меню работают по образцу «раскрывающейся навигации» WAI-ARIA: `aria-expanded`, Esc закрывает, фокус возвращается на кнопку, клик вне меню закрывает. Открыто не больше одного мега-меню.
- **Счётчик корзины:** сумма `qty` из `etsgrid:cart:v1`. 0, пустой или испорченный ключ → счётчик скрыт. Обновляется без перезагрузки.
- **Палитра:** переключение не перезагружает страницу и сохраняется между страницами.
- **Узкий экран:** на 320 px нет горизонтальной прокрутки.

## 5. Доступность
- Ссылка «Перейти до змісту» — первый фокусируемый элемент, видна при фокусе.
- Ориентиры страницы: `header`, `nav` (с `aria-label`: «Основне меню», «Хлібні крихти», «Меню у підвалі»), `main`, `footer`. Ровно один `h1` на странице.
- Видимый фокус (`--color-focus`, ≥ 3:1 к фону) на всех интерактивных элементах в обеих палитрах.
- Области касания ≥ 44 × 44 px в шапке, меню, подвале.
- Все пары «текст / фон» из токенов проходят WCAG AA: ≥ 4,5:1 для текста, ≥ 3:1 для крупного текста и элементов интерфейса. Рискованная пара — `#FFB547` на светлом фоне: акцент на дне используется только как заливка кнопки с тёмным текстом, не как цвет текста.
- `prefers-reduced-motion: reduce` отключает анимации и переходы между страницами.

## 10. Решения в этой спецификации
После утверждения записываются в DECISIONS одной записью:
1. Адреса, которых нет в 03 (§3.1), и стиль транслита.
2. `structure.json` — источник навигации, категорий (включая пустые), услуг, документов, контактов.
3. `catalog.json` хранит структуру образца; `id` берётся из `slug` в парсере загрузчика.
4. `trailingSlash: 'always'`, временный домен `https://ets-grid.test`.
5. Скрипты шапки — ванильный JS; Preact только для тяжёлых островов.
6. Переходы между страницами — CSS View Transitions без `<ClientRouter />`.
7. Палитра — атрибут `data-palette` на `<html>`; переключатель только в мокапе.
8. До раунда дизайна — системные шрифты.
9. Состав zip: `site/` + `source/`; свой `serve.mjs` вместо `npx serve` (на машине показа не нужен интернет).
10. Ключи `localStorage` и событие `etsgrid:cart-change` — контракт между модулями.
11. Новая спецификация SPEC-009 «Формы заявок» (общая форма расчёта, форма с предзаполненным товаром, маска +380, honeypot, имитация отправки); поиск отнесён к SPEC-005.
