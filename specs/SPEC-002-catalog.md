## 1. Цель
Посетитель за минуту находит подходящий товар в любом из 4 уровней: страница уровня ведёт в подкатегории и подборщик, листинг даёт главный фильтр-чипами, фасеты со счётчиками и никогда не показывает пустую выдачу. Двигает метрики ТЗ §2: доля лидов с параметрами подборщика ≥ 50 %, конверсия ≥ 2,5 %.

## 3. Контракт

### 3.1. Конфиг фильтров `src/data/filters.json`
Машиночитаемая копия 03 §2, дополненная там, где 03 даёт только имена фасетов (solar, battery, carport), значениями из ТЗ §9.3–9.5. Для каждого уровня: `primary` (главный фильтр) и `facets[]`. Фасет:

| Поле | Смысл |
|---|---|
| `key` | ключ в URL и в событии `filter_apply` |
| `label` | подпись на украинском |
| `ui` | `visual-chips`, `chips`, `toggle`, `checkbox`, `checkbox-icons`, `ranges`, `range-slider`, `search-select` |
| `field` | откуда брать значение товара: `type`, `scenarios`, `stock`, `brand`, `country`, `price`, `attrs.<имя>` или вычисляемое `price_per_w` |
| `values` | `[[значение, подпись], …]` для перечислений |
| `ranges` | `[[от, до, подпись?], …]` для диапазонов; товар попадает в диапазон, если `от < x ≤ до` (первый диапазон включает 0, у последнего `до = null` — без верхней границы). Подпись по умолчанию строится из границ и `unit`; своя подпись — для дискретных значений (порты: `[[0,1,"1"],[1,2,"2"],[2,4,"3–4"]]`) |
| `unit` | единица для подписей диапазонов (`кВт`, `Вт`, `кВт·год`, `kWp`) |
| `values: "auto"` | значения берутся из данных листинга (бренд, страна, хімія); плейсхолдеры отбрасываются |

Поле-массив (`connectors`, `scenarios`, `control`, `bundle`) совпадает, если содержит любое из выбранных значений.

**Отклонения от 03 и ТЗ (записываются в DECISIONS при утверждении):**
1. **Тип `cable` «Кабель / адаптер»** в главном фильтре зарядок, у `cable-gbt-type2` в `catalog.json` тип меняется с `portable` на `cable` (закрывает Q-3). Без этого адаптер попадает в «Портативна станція».
2. **Диапазоны мощности зарядок — по 03** (`до 3,7 · 3,7–7 · 7–11 · 11–22 · 22–60 · 60–160 · 160–240 кВт`), а не по подписям ТЗ §9.2 (`3,7 · 7 · 11 · 22 · 30–60 · 80–160 · 180–240`): у ТЗ между диапазонами дыры (станция 70 кВт не попала бы никуда), 03 — машиночитаемый и сплошной.
3. **Диапазоны инверторов** ТЗ §9.3 (`3–5 · 6–10 · 12–30 · 50+`) делаются сплошными: `до 5 · 5–10 · 10–30 · від 30 кВт`.
4. **Фасет «Час автономії»** (ТЗ §9.4, вычисляемый) переносится в SPEC-004: формула 3.2 и коэффициенты живут в `calc.json`, которым владеет SPEC-004.
5. **Сортировка «Новинки»** видна, но неактивна с пометкой «немає дати появи товару», пока в данных нет поля `added_at`, — порядок новизны не выдумываем (ревизия 3, D-031).

### 3.2. Логика фильтрации `src/lib/filters/` (чистые функции, без DOM)

| Функция | Что делает |
|---|---|
| `parseState(search, config)` | строка запроса → состояние; неизвестные ключи и значения отбрасываются |
| `serializeState(state, config)` | состояние → строка запроса в каноническом порядке ключей; пустое состояние → `''` |
| `applyFilters(products, state, config)` | «ИЛИ» внутри фасета, «И» между фасетами |
| `facetCounts(products, state, config)` | для каждого значения: число товаров при текущих прочих фильтрах плюс это значение (03 §2) |
| `visibleFacets(products, config)` | фасет показывается, если хотя бы у одного товара листинга есть его поле; значения-плейсхолдеры (`[БРЕНД]`) не предлагаются |
| `missingFacets(levelProducts, config)` | фасеты уровня, по которым **во всём уровне** нет реальных данных (бренд, страна, гарантия, совместимые инверторы): показываются в колонке и шторке неактивными с пометкой «Дані надасть замовник» (ревизия 3, D-031). Фасеты, у которых данные в уровне есть, но не в этой категории, не показываются — они к категории не относятся |
| `sortProducts(products, sort, level)` | см. §3.3 |
| `nearestProducts(all, context, n = 3)` | для пустой выдачи: товары того же уровня, ближайшие по главной метрике к выбранному диапазону, иначе — первые по каталогу |

**Строка запроса:** значения одного фасета через запятую, диапазоны — по своим границам, цена — `від-до`:
`?type=wall_ac,dc&power_kw=60-160&connectors=type2&price=20000-35000&sort=price-asc`.
Ключи — `key` фасета; `sort` — отдельный ключ. Порядок ключей при сериализации — порядок фасетов в конфиге.

### 3.3. Сортировка
| Значение `sort` | Подпись | Правило |
|---|---|---|
| (нет) | Популярні | порядок `catalog.json` (данных о популярности нет; в боевом — из CMS/аналитики) |
| `price-asc` | Дешевші | по цене `price_equipment ?? price_turnkey_from`; без цены — в конце |
| `price-desc` | Дорожчі | обратный; без цены — в конце |

| `new` | Новинки | видна неактивной с пометкой до появления `added_at` (§3.1 п. 5) |

### 3.8. Перестановка карточек — animateLayout (ревизия 4, D-045)
Когда фильтр или сортировка меняет выдачу, карточки не перескакивают, а переезжают на новые места: видно, что ушло и что осталось.
- **Функция** — `animateLayout` из `motion` (вышла из раннего доступа Motion+, в `@motionplus/core/animate-layout` помечена устаревшей). Остров остаётся на Preact: функция ванильная, React не нужен.
- **Как:** та же правка `hidden` и `order`, что сейчас, выполняется внутри `animateLayout(results, () => { … }, options)`; область — контейнер выдачи `.cf-results`, у каждой карточки `data-layout` (в `ProductCard.astro`, атрибут без значения, на вид не влияет).
- **Движение** (DESIGN.md «світло вмикається»): оставшиеся карточки едут `transform` 320 мс (`--dur`) по `[0.22, 1, 0.36, 1]` (`--ease-out`), без перелёта; появившиеся — `opacity 0 → 1` за те же 320 мс; ушедшие скрываются сразу (`hidden`), чтобы «Знайдено: N» и счётчики оставались мгновенными (§4). Ширина и высота карточек не анимируются — только позиция.
- **Когда не анимируем:** первое применение состояния из URL при загрузке; пока открыта шторка mobile (выдачу не видно — правка мгновенная, после «Показати N товарів» карточки уже на месте); `prefers-reduced-motion` — правка без `animateLayout`; новое изменение посреди анимации прерывает её и ведёт к последнему состоянию.
- **Вес:** `animateLayout` ≈ +13 КБ gz к ванильному `motion` (замер D-045); листинг и страница уровня остаются в 150 КБ (с учётом островов, SPEC-001 AC-24).
- Хиты на главной — та же функция и те же правила (SPEC-006 §4.7).

- Desktop: плитки в ряд над колонкой и выдачей, ширина по содержимому (min 10rem), перенос на вторую строку допустим. Mobile: горизонтальная прокрутка с `scroll-snap` (ТЗ §6.3), ширина плитки 9rem, последняя плитка «выглядывает».
- Доступное имя плитки — как у чипа сейчас: «Настінна AC, 3 товари».

**Б. Фасеты по смыслу** (H-013). Чистая функция `rankFacets(facets, counts, state, bounds) → { open, folded }` в `src/lib/filters/`:
- Фасет **раскрыт**, если у него есть выбранное значение (из URL или кликом) **или** он делит листинг: ≥ 2 значений со счётчиком > 0 при пустом состоянии; интервал (`price`) — если `intervalBounds` даёт `min < max`. Раскрытых не больше **4** (ТЗ §6.3 «первые 4 раскрыты»), остальные сворачиваются в порядке конфига.
- Ранжирование считается **один раз при загрузке** по полному листингу, не по текущей выдаче: фасеты не прыгают между группами во время фильтрации (ТЗ §9.1 п. 3 «ничего не прыгает»). Фасет с выбранным значением раскрывается при выборе из свёрнутых, обратно не сворачивается до перезагрузки.
- Свёрнутые фасеты — под одним `<details class="cf-more">` с заголовком «Ще N фільтрів» (N — число фасетов), внутри — те же `<details>` по фасету, закрытые. Открытие «Ще N фільтрів» и каждого фасета — через `animateLayout` колонки (как FAQ на главной, 320 мс `--ease-out`), соседи съезжают, а не прыгают.
- Фасеты без данных (D-031, `missingFacets`) — не пять заголовков, а **одна плашка** под списком: «Ще M фільтрів зʼявляться з даними замовника: Бренд · Гарантія · Сумісні інвертори · Час автономії» — пунктирная рамка `placeholder` (The Dashed Means Missing Rule: данные надаст замовник), `aria-disabled="true"`, `data-missing-facets="brand,warranty,…"`. AC-29 переписывается под плашку: все ключи на месте, заголовки перечислены текстом.
- Пример на текущем каталоге, `/batarei/` (3 товара): раскрыты `capacity_kwh` (2 непустых значения), `voltage` (2), `autonomy_h` (2, вычисляемый фасет SPEC-004), `scenarios` (2); свёрнуты `chemistry` (1 значение), `max_expand_kwh` (1), `price` (цена у одного товара → границы совпадают), `stock` (делит, но лимит 4 исчерпан); плашка — `inverters`, `brand`, `warranty`. Колонка укорачивается с 11 заголовков до 4 + «Ще 4 фільтри» + плашка (уточнено по данным при написании AC-33).
- Страница уровня и шторка mobile — те же правила; в шторке «Ще N фільтрів» тоже `<details>`.

**В. Огоньки вместо инверсии.** Выбранный чип значения и выбранная плитка не заливаются `ink`, а **загораются**: точка-лампа 6 px (`::before`, плитка — `::after` как у героя) из `--color-accent`, в покое `opacity .3`, выбранная — `opacity 1` + ореол `box-shadow 0 0 10px` акцента (The One Lamp Rule: акцент только на огоньке и на одной primary-кнопке, рамки и заливки не трогает); текст 700, рамка `ink`. Переход `--dur-fast` `--ease-out`, только `opacity`/`box-shadow` огонька. Это меняет правило DESIGN.md «Chips → State: инверсия» для **фильтр-чипов**; теги характеристик в карточке остаются как есть. Чипы выбранных фильтров с «×» над выдачей — тоже с огоньком. Кнопки-фильтры хитов на главной (`HitsCarousel`) переводятся на то же правило мелкой ревизией SPEC-006 после утверждения.

**Г. Живые числа — `AnimateNumber`** (как SPEC-004 §3.7, SPEC-006 `LiveNumber`): «Знайдено: **N**», «Показати **N** товарів» в шторке, счётчики плиток и значений раскрытых фасетов. 450 мс, `[0.16, 1, 0.3, 1]`, `locales="uk-UA"`; при первом показе разряды не крутятся (значение сразу); `prefers-reduced-motion` — мгновенно; разряды `aria-hidden`, доступный текст и `aria-live` «Знайдено: N» (§5, раз в 300 мс) остаются обычным текстом. Счётчики в свёрнутых фасетах — обычный текст (их не видно).
- **Переезд острова на React** (D-044): `src/islands/catalog/CatalogFilters.tsx` → `src/islands/react/catalog/CatalogFilters.tsx` (прагма `@jsxImportSource react`), стили остаются в `catalog-filters.css`; контракт §3.7 (остров не рендерит карточки, ставит `hidden` и `order`) не меняется; `src/islands/catalog/` удаляется. Вес: цель ≤ 150 КБ gz на листинге и уровне (оценка: 78,7 сейчас + React ≈ 41 + `animateLayout` ≈ 13 + `AnimateNumber` ≈ 5 ≈ 138), лимит теста бюджета для страниц с React-островом — 250 (D-062, SPEC-001 AC-24). **Факт 15.10:** уровень `/batarei/` 180,5 КБ gz, листинг 168,2 — цель 150 не достигнута (React 41 + полный `motion` ≈ 45 ради `animateLayout`), лимит соблюдён; оптимизация — отдельным шагом (D-063).

**Д. Перестановка карточек** — по §3.8 без изменений (`animateLayout`, 320 мс, `data-layout`), AC-30…AC-32 остаются и закрываются вместе с ревизией 5.

**Е. Ритм колонки и панели.** Заголовок фасета — `title` 700 (как заголовки узлов «Системи»), между фасетами `space-m` и линия `line`; колонка `position: sticky; top: calc(var(--header-h) + var(--space-m))`, если короче окна. «Знайдено: N» — `title`, число `num`; сортировка остаётся нативным `<select>` по правилу «Inputs / Fields». Поверхность — день (`day-bg`), как у акта IV «Вітрина»: каталог — витрина, ночь остаётся первому экрану и форме. Карточка товара в этой ревизии не меняется (отдельная ревизия вместе с SPEC-003).

**Ж. Без JS и reduced-motion.** Без JS плитки и фасеты по-прежнему `js-only`, товары и «Популярні добірки» в HTML (§4). При `prefers-reduced-motion`: огоньки принимают конечное состояние без перехода, числа ставятся сразу, `animateLayout` не вызывается (The Static Night Rule).

**Мокап → боевой (дополнение к §6):** порог «4 раскрытых» и признак «показувати згорнутим» — в CMS рядом с порядком фасетов; иконки типов — в CMS к значению главного фильтра.

**Касания:** SPEC-006 (огоньки на кнопках-фильтрах хитов — мелкая ревизия), SPEC-004 рев. 2 (та же схема переезда на React, общий `src/islands/react/`), DESIGN.md (правило Chips, раздел «Иконки» — новые имена), SPEC-010 (эталоны листинга и уровня пересъёмка после утверждения дизайна, AC-14).

### 3.10. Мини-галерея карточки — 5 кадров на Carousel (ревизия 6, D-065)
Карточка листинга показывает не одно иллюстративное фото, а **5 кадров** с гортанием — по образцу галерей «Обʼєкти» на главной (SPEC-006 §4.10, D-061).

- **Наборы кадров по типу товара** — `src/lib/photos.ts`: `FRAME_SETS: Record<FrameSet, PhotoKey[]>` (ровно 5 ключей в наборе) и `PRODUCT_FRAME_SET: Record<slug, FrameSet>`. Наборы: `wallbox` (wall_ac ×3), `duo` (pedestal_ac), `dc` (dc ×2), `split-dc`, `dc-battery`, `portable`, `cable`, `panel`, `inverter`, `solar-kit`, `home-battery`, `bess` (commercial + industrial), `carport` (single / double / row) — 13 наборов. Первый кадр товара — его нынешняя иллюстрация `PRODUCT_ILLUSTRATION[slug]` (если есть), дальше — кадры набора без повтора; функция `productFrames(product): PhotoKey[]` (чистая, тест). Кадры «Обʼєкти» (`case-*`) переиспользуются там, где подходят по смыслу (навесы → `carport`, дома с панелями → `solar-kit` / `panel`, промышленные → `bess`); остальное — новые кадры Pexels, каждый — строкой в `CREDITS.md`, `alt` на украинском с пометкой «(ілюстрація)».
- **Реальные фото заказчика** (`images`, Q-6) заменяют набор: при `images.length ≥ 2` галерея из них, при одном — одно фото без карусели, как сейчас; метка «Ілюстративне фото» только на иллюстрациях.
- **Остров** `src/islands/react/CardGallery.tsx` (React, D-044) — копия подхода `CaseGallery`: `Carousel` (`snap="page"`, `loop={false}`, `itemSize="fill"`, `gap` 0), кадры — серверные `<picture>` (`Photo.astro`) через слоты `shot0…shot4`, стрелки «Попередній / Наступний кадр: {назва товару}» и точки-лампы (`role="tab"`), как у «Обʼєкти». Без JS — первый кадр, остальные не торчат (`overflow: hidden`). `client:visible`. Бейдж сценария — поверх галереи (absolute в `.product-card__photo`), метка «Ілюстративне фото» — в каждом кадре (как в «Обʼєкти»), чтобы читалась на любом кадре.
- **Где галереи нет:** `variant="compact"` (пустая выдача, перекрёстные блоки на странице товара) и карточки хитов на главной (`HitsCarousel` — карусель в карусели не делаем: перетаскивание конфликтует) показывают только первый кадр; у `ProductCard` появляется свойство `gallery?: boolean` (по умолчанию `true` для `listing`), `HomeHits.astro` передаёт `gallery={false}`.
- **Движение:** гортание — `Carousel`; точка активного кадра — янтарная лампа (The Lit Chip Rule), остальные `line`; `prefers-reduced-motion` — мгновенное переключение (Carousel сам), ничего не движется само.
- **Вес:** `Carousel` уже в бандле главной; на листинге +≈10 КБ gz один раз на страницу (остров один на карточку, модуль общий); лимит 250 (D-062). **Факт 15.10:** листинг 176,7 КБ gz (было 168,2), уровень `/batarei/` 189,1 (было 180,5). Страница поиска `/poshuk/` и `compact`-карточки — без галереи (`gallery={false}`), React там не появляется.
- **Доступность:** каждая стрелка и точка с именем, кадры — `<picture>` с `alt`; перестановка карточек (§3.8) остаётся: `data-layout` на `<article>`, галерея внутри не мешает.

### 3.10.1. Галерея без задержки LCP и зона касания точек (ревизия 6.1, D-069; Q-16, Q-17)
**Замер 15.10** (`qa/README.md`, сводный замер; телефон 412×823, CPU ×4, Slow 4G): LCP листинга 6,35 с — первый кадр первой карточки ждёт запроса 1,45 с (`loading="lazy"`, низкий приоритет), грузится 1,29 с и **перерисовывается через 3,61 с**, когда остров `CardGallery` (`client:visible`) гидратируется и заново вставляет кадры слотов. Lighthouse `target-size`: точки галереи 6–9 px при минимуме 24 px (WCAG 2.2 AA, 2.5.8).

- **Гидратация по намерению.** Остров `CardGallery` оживает не при появлении в кадре, а при первом намерении листать: `pointerenter` / `pointerdown` / `touchstart` / `focusin` на фото карточки. Своя клиентская директива Astro `client:intent` (`src/directives/intent.ts`, регистрируется интеграцией в `astro.config.mjs` через `addClientDirective`) — слушает события на `astro-island` с `{ once: true, passive: true }`, затем вызывает `load()`; при `prefers-reduced-motion` поведение то же. До гидратации карточка — серверный HTML: первый кадр, метка, бейдж; **стрелки и точки уже видны** (серверная разметка навигации в `ProductCard`, `pointer-events` и `aria-disabled="true"` до гидратации), чтобы раскладка не прыгала и было понятно, что кадров несколько. Первое касание стрелки гидратирует остров и выполняет листание (клик пересылается после `load()`).
- **Первый ряд — без lazy.** Первые `N` карточек листинга (N = 3 на ≥ 960 px, 1 на телефоне — считается на сервере как «первые 3 по порядку каталога») рендерят первый кадр с `loading="eager"`, `fetchpriority="high"`; остальные кадры и карточки — `lazy`. Свойство `ProductCard` `priority?: boolean`, `Catalog` передаёт его первым трём. В остальных местах (поиск, compact, хиты) — без изменений.
- **Зона касания точек 24 px** без смены вида: `.pgal__dot` — прозрачная кнопка `min-width/min-height: 24px`, видимый кружок — `::before` 6 px (активный — масштаб 1,4, лампа). Стрелки уже 32 px — без изменений. То же правило — для точек `CaseGallery` и `HitsCarousel` на главной (SPEC-006 рев. 6.2).
- **Тесты доступности** проекта получают тег `wcag22aa` (axe) на страницах каталога — чтобы `target-size` ловился автоматически.
- **Цель:** LCP листинга на том же профиле ≤ 2,5 с; Accessibility Lighthouse 100; вес JS не растёт (директива ≈ 0,5 КБ, React грузится позже — по намерению).

### 3.11. Ночной порог уровня и листинга (ревизия 7, D-067)
Применение SPEC-001 §3.10 к страницам каталога.
- **Уровень** `/{level}/`: `threshold="rich"`; в слот `top` переезжает блок 1 §3.4 — мини-герой `LevelHero` (H1, строка ценности, CTA «Підібрати за 3 питання», фото). Цвета героя — токены ночи (`--color-*` под `data-surface="night"`), фото — `rounded.l`, `priority`, без подложки `surface`. Секция плиток подкатегорий (блок 2) получает `seam="dawn"`. Остальной порядок блоков §3.4 не меняется, AC-15 остаётся.
- **Листинг и ЧПУ-страница:** `threshold="min"`; в пороге — H1, строка `hint` (только на листинге), «Популярні добірки» и ссылка «Не знаєте, що обрати? Підбір за 3 питання». Каталог (`Catalog`) — первая секция дня со `seam="dawn"`: плитки главного фильтра стоят сразу под світанком, на дне (остров фильтров не делится на две поверхности).

## 4. Поведение и состояния
- **Выбор значения:** выдача, счётчики, «Знайдено: N» и URL (`history.replaceState`) меняются мгновенно, без перезагрузки; событие `filter_apply` с ключом, значением и числом результатов.
- **Счётчики:** значение с 0 неактивно (`aria-disabled`, серое), но остаётся на месте — ничего не прыгает. Выбранное значение с 0 (пришло из URL) активно, чтобы его можно было снять.
- **Снятие:** повторный клик по значению, «×» на чипе выбранного фильтра, «Скинути все» — очищает все фильтры. На ЧПУ-странице «Скинути все» ведёт на листинг категории без фильтров.
- **«Популярні добірки»:** под заголовком листинга — ссылки на ЧПУ-страницы этой категории (если есть); видны всегда, с JS и без.
- **URL:** перезагрузка и «Назад» восстанавливают состояние; невалидные значения молча отбрасываются и убираются из URL.
- **Пустая выдача** (устаревший URL или пустая категория): текст «Таких товарів немає. Скиньте фільтр або дайте нам 3 питання — підберемо.» (для зарядок — «Таких станцій немає…»), кнопка «Скинути фільтри» (если фильтры есть), 3 ближайших товара (`nearestProducts`), место для формы подбора (SPEC-009).
- **Без JS:** все товары листинга и их цены — в HTML; чипы главного фильтра и фасеты не показываются (`js-only`), ЧПУ-страницы доступны через «Популярні добірки». Фильтрация отправкой формы — в боевом сайте (см. §6).
- **Шторка (mobile):** открывается кнопкой «Фільтри (N)», фокус внутри, Esc и кнопка «Закрити» закрывают и возвращают фокус на кнопку; «Показати N товарів» закрывает шторку и прокручивает к началу выдачи.

## 5. Доступность
- Чипы и значения фасетов — `<button aria-pressed>` (мультивыбор) или `role="radio"` в `role="radiogroup"` для переключателей; подпись содержит счётчик: «Type 2, 4 товари».
- Каждый фасет — `<fieldset>` с `<legend>` или группа с `aria-labelledby`.
- «Знайдено: N» — в `aria-live="polite"`, обновляется не чаще раза в 300 мс.
- Ползунок цены дублируется полями «від» и «до» с подписями.
- Шторка — нативный `<dialog>` с заголовком «Фільтри».
- Цвет наличия всегда сопровождается текстом.
- Области касания ≥ 44 px, видимый фокус, reduced-motion для открытия шторки.

## 6. Мокап → боевой

| Что | В мокапе | В боевом сайте |
|---|---|---|
| Фильтрация | на клиенте, по индексу товаров страницы | SSR читает строку запроса; форма фильтров работает без JS (ТЗ §9.1 п. 6) |
| `noindex` для комбинаций | невозможен в статике: canonical листинга всегда на чистый адрес | сервер ставит `noindex, follow` при любых параметрах, кроме ЧПУ (ТЗ §9.1 п. 5) |
