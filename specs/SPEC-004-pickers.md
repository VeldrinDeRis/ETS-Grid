## 1. Цель
Покупатель отвечает максимум на 3 вопроса и на том же экране видит результат в понятных единицах: хватит ли сети, какая станция подходит, сколько часов света даст батарея, сколько панелей нужно, что даст навес. Результат ведёт в заявку с уже заполненными параметрами. Двигает метрику ТЗ §2 «≥ 50 % заявок с параметрами подборщика» и проверяет гипотезы H-003 и H-005.

## 2. Источники
- ТЗ §6.1 блок 3 («Хватит ли мощности?»), §6.2 п. 3 (подборщик уровня), §6.6 (лендинг Solar Carport), §7 (сценарии и таблица подборщиков), §9.4 (фасет «Час автономії»), §10.4 (`picker_complete`).
- `03_struktura_i_filtry.md` §3.1–3.4 — формулы; требование вынести коэффициенты в `src/data/calc.json`.
- Концепция студии §4.1 («Світломір»: окна загораются по мере роста часов), §4.3 («Перевірка вводу»), §5 («свет включается», 300–600 мс).
- Референсы: `dc-store-external.html` («Хватит ли вашей мощности?», текст результата), `ets-grid-energy-ecosystem-editorial.html` (конфигуратор навеса, те же коэффициенты, что в 03 §3.4).
- Решения: D-007 (ванильный `motion`), D-026, D-027 п. 3 (фасет автономии перенесён сюда).

### 3.2. Формулы `src/lib/calc/` (чистые функции, тесты до кода)

| Функция | Вход | Выход |
|---|---|---|
| `powerCheck({ needKw, gridKw }, stations, calc)` | нужная мощность, ввод | `station` (минимальная стационарная станция с `power_kw ≥ need` нужного тока, без типов `dc_battery`, `portable`, `cable`; при равенстве — меньший `input_min_kw`. Станция с накопителем — не базовый выбор, а решение при дефиците), `current`, `deficit = max(0, input_min − grid)`, `outcome`: `ok` (+ запас) · `ac_deficit` (+ `smallerKw` — самая мощная AC с `input_min ≤ grid`, или `null`) · `dc_deficit` (+ `batteryKwh = ceil(deficit × 0,5 / 10) × 10`, + `batteryStation` — станция `dc_battery` с `input_min ≤ grid`, если есть) |
| `chargingPicker({ where, connector, phases, gridKw }, stations, calc)` | 3 вопроса ТЗ §7 | `fits` — до 3 станций сценария, разъёма и фаз с `input_min ≤ grid`, по убыванию мощности; `needsMore` — самая подходящая станция, которой не хватает ввода, с решением из `powerCheck` |
| `batteryHours(loadsW, capacityKwh, calc)` | нагрузка, ёмкость | `capacity × 1000 × 0,9 × 0,95 / load` |
| `batteryPicker({ loads, hours, hasSolar }, batteries, calc)` | 3 вопроса ТЗ §7 | `neededKwh`, рекомендованная батарея и число модулей (если влезает в `max_expand_kwh`) или «під розрахунок», `hoursWithIt` («≈ N год світла») |
| `solarSize({ monthlyKwh, purpose, mount }, kits, calc)` | 3 вопроса ТЗ §7 | `kwp` (до 0,1), `panels`, `areaM2`, ориентир цены по ₴/kWp демо-комплекта (с меткой «демо-ціна») или «Ціна за розрахунком» |
| `carportConfig({ places, chargers, storage }, calc)` | 3 вопроса ТЗ §7 | `kwp`, `panels`, `evPorts` (0 без зарядок), `storageKwh` (0 без накопителя), `co2TYear`, ближайший тип из каталога; цена — «Ціна за розрахунком» (в каталоге нет цен навесов) |
| `autonomyHours(product, calc)` | товар-батарея | часы на «базовых потребностях» для фасета §3.5 |

Станции для подборщиков — товары уровня «Зарядні станції», кроме типа `cable`.

**Общее для всех:**
- Результат на том же экране, обновляется сразу при изменении ответа, текстом в `aria-live="polite"`.
- Каждый результат заканчивается строкой «Оцінка орієнтовна. Точний розрахунок — після обстеження.» (03 §3.1).
- CTA «Отримати розрахунок» (Carport — «Отримати проєкт навісу») → `routes.quoteWith(params)`: `/kontakty/?picker=<уровень>&<ответы>&<результат>#rozrakhunok`. SPEC-009 читает параметры и предзаполняет форму (гипотеза H-003).
- Событие `picker_complete` с уровнем, ответами и результатом — при первом полном ответе и при переходе по CTA.
- Рекомендованные товары — ссылками на `/product/{slug}/` с ценой по правилу `Price`.

**Результат батарей — «окна загораются»** (концепция §4.1, H-011): силуэт дома из 6 окон; горит `min(6, ceil(часы / 4))` окон, загорание — opacity 300–600 мс через ванильный `motion` (`animate`), при `prefers-reduced-motion` — сразу в конечном состоянии. Картинка дублирует текст, не заменяет его (`aria-hidden`).

### 3.5. Фасет «Час автономії» (перенесён из SPEC-002, D-027 п. 3)
- Поле `autonomy_h` вычисляется для батарей по формуле 3.2 на «базових потребах» (`autonomy_reference_loads`: світло + інтернет + холодильник = 300 Вт).
- Фасет в `filters.json` уровня `battery`: подпись «Час автономії (базові потреби)», диапазоны `до 12 · 12–24 · 24–48 · від 48 год`.
- На текущем каталоге: домашняя 10,24 кВт·год → ≈ 29 год (`24–48`); BESS 100 и 215 → `від 48`.
- Это ревизия SPEC-002 (новое вычисляемое поле в `fieldValue`), записывается в её «Ревизии».

### 3.6. Без JS
Остров не работает → вместо формы видна таблица типовых сценариев, посчитанная на сервере теми же функциями (концепция §4: «без JS — таблица типовых сценариев»):
- зарядки: нужная мощность 7 / 22 / 60 / 120 кВт × ввод 15 / 50 / 100 кВт → вывод;
- батареи: «базові потреби» и «+ котел і насос» × домашняя батарея каталога → часы;
- СЕС: 200 / 400 / 800 кВт·год в месяц → kWp, панели, площадь;
- Carport: 2 / 8 / 20 мест → kWp, панели, порты, накопитель.

Таблица в HTML всегда (поисковик и браузер без JS её видят), с JS — скрыта (`no-js-only`).

## 4. Поведение и состояния
- Значения по умолчанию дают осмысленный результат сразу (ввод 50 кВт и зарядка 60 кВт — пример «не вистачає»; 20 машиномест — как в референсе).
- Поля чисел и ползунки синхронизированы; ввод за пределами диапазона прижимается к границе с подсказкой «від … до …».
- Нет подходящей станции (`fits` пуст, `needsMore` пуст) → «Під ваші умови готової моделі немає — підберемо індивідуально» + CTA.
- Без выбранных потребителей у батарей → подсказка «Оберіть, що має працювати», результата нет, CTA неактивна.
- Если `solar.tariff_uah_per_kwh = null` — переключателя «рахунок, ₴» нет.

## 5. Доступность
- Каждый вопрос — `<fieldset>` с `<legend>`; варианты — радиокнопки или чекбоксы, ползунок продублирован числовым полем с подписью и единицей.
- Результат — `role="status"` / `aria-live="polite"`, обновление не чаще раза в 300 мс.
- Цвет «вистачає / не вистачає» дублируется текстом и значком.
- Окна дома — `aria-hidden`, смысл в тексте «≈ N год світла».
- `prefers-reduced-motion`: никакой анимации, результат сразу.
- Области касания ≥ 44 px, видимый фокус, проход с клавиатуры.
