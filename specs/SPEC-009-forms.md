## 1. Цель
Любой путь по сайту заканчивается короткой формой, в которую уже подставлено всё, что посетитель выбрал: товар, ответы подборщика, страница-источник. Менеджер получает заявку «с техзаданием». Двигает метрики ТЗ §2: конверсия ≥ 2,5 %, ≥ 50 % заявок с параметрами подборщика.

## 2. Источники
- ТЗ §6.1 блок 11 (4–5 полей: имя, телефон, тип объекта, что интересует, мессенджер), §10.2 (формы → CRM с параметрами подборщика, UTM и страницей; honeypot + серверная проверка + rate limit; маска +380, понятная валидация), §10.4 (`quote_submit`), §6.4 (кнопка «Розрахувати» с товаром).
- Инструкция 02 §2 (заглушка отправки, без внешних сервисов и ключей), правило 11 (подписи полей, клавиатура).
- Решения: D-013 (имитация на клиенте), D-027 п. 10 (`quoteFor`), D-029 п. 5 (`quoteWith`), D-031.

## 3. Контракт

### 3.1. Виды форм (один компонент `LeadForm`, свойство `kind`)
| `kind` | Где | Заголовок | Видимые поля |
|---|---|---|---|
| `quote` | `/kontakty/#rozrakhunok` — сюда ведут все CTA «Розрахувати» и «Отримати розрахунок» | Розрахунок під ключ | імʼя, телефон, тип обʼєкта, що цікавить, месенджер |
| `final` | главная, блок 11 | Назвіть майданчик — решта на нас | те же 5 |
| `level` | страницы уровней (блок `form`), пустая выдача | Підберемо під ваш обʼєкт | імʼя, телефон, месенджер (+ уровень скрыто из страницы) |
| `carport` | `/solar-carport/`, блок формы | Отримати проєкт навісу | імʼя, телефон, місто, месенджер |

Видимых полей — не больше 5 (ТЗ §6.1). Комментарий — необязательное раскрываемое поле «Додати коментар».

### 3.2. Поля и проверка
| Поле | Обязательно | Правило |
|---|---|---|
| Імʼя | нет | до 80 символов |
| Телефон | да | маска `+380 XX XXX XX XX`; принимаются ввод с 0, 380, +380, пробелами и скобками; ошибка: «Вкажіть номер у форматі +380 XX XXX XX XX» |
| Тип обʼєкта | нет | Дім · Бізнес / паркінг · АЗС / траса · Автопарк · Інше |
| Що цікавить | нет | мультивыбор 4 уровней; по умолчанию отмечен уровень страницы-источника |
| Месенджер | нет | Дзвінок · Telegram · Viber |
| Місто (Carport) | нет | текст |
| Коментар | нет | до 1000 символов |

Функции `src/lib/leads.ts`: `normalizePhone(input) → '+380XXXXXXXXX' | null`, `formatPhone`, `validateLead(fields) → errors`.

### 3.3. Параметры, которые форма подхватывает
- `?product={slug}` (SPEC-002, SPEC-003) → блок «Товар: {название} · {цена}» над полями, отмечается уровень товара.
- `?picker={вид}&…` (SPEC-004) → блок «Ваші параметри»: человекочитаемая сводка (`describePicker(params)`), например «Потрібна зарядка 60 кВт, ввід 50 кВт → не вистачає 15 кВт, накопичувач ≈ 10 кВт·год». Посетитель может убрать параметры кнопкой «Прибрати».
- UTM (`utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`) при первом входе на сайт сохраняются в `sessionStorage` (`etsgrid:utm`) и прикладываются к заявке.
- Страница-источник: `document.referrer` в пределах сайта или текущий адрес.

### 3.4. Заявка (контракт для CRM, ТЗ §10.2)
```json
{
  "type": "lead",
  "kind": "quote | final | level | carport",
  "id": "L-20261014-AB12",
  "created_at": "ISO 8601",
  "name": "…", "phone": "+380…", "object_type": "business", "interests": ["charging", "battery"],
  "messenger": "telegram", "city": null, "comment": null,
  "product": "ets-dc-60" ,
  "picker": { "picker": "power", "need_kw": "60", "grid_kw": "50", "outcome": "dc_deficit" },
  "source_url": "/zaryadni-stantsii/", "utm": { "utm_source": "…" }
}
```

### 3.5. Отправка
- **С JS:** проверка → при ошибках фокус на первое поле с ошибкой и сводка ошибок вверху формы → при успехе заявка пишется в `console.info('[lead]', …)` (заглушка `TODO: integration`), событие `quote_submit` с `kind`, `has_picker`, `has_product` → переход на `/dyakuyemo/?type=lead&id={id}` (в адресе только номер, без персональных данных).
- **Без JS:** форма `method="post" action="/dyakuyemo/?type=lead"`: персональные данные не попадают в адрес; статический сервер показывает страницу «Дякуємо», данные в мокапе никуда не уходят (видимая пометка на странице «Дякуємо» в мокапе).
- **Антиспам:** поле-ловушка (honeypot) `website` — визуально скрыто, `tabindex="-1"`, `autocomplete="off"`; заполнено → заявка молча отбрасывается. Отправка раньше чем через 3 с после показа формы — отбрасывается. Серверная проверка и rate limit — в боевом сайте.
- **Согласие:** под кнопкой строка «Надсилаючи заявку, ви погоджуєтеся з [політикою конфіденційності]» со ссылкой на `/polityka-konfidentsiinosti/` (текст политики — заказчик).

## 4. Поведение и состояния
- Ошибка поля показывается после ухода из поля или при отправке, исчезает при исправлении.
- Кнопка «Надіслати заявку»; во время «отправки» — «Надсилаємо…» и неактивна (имитация ≤ 600 мс).
- Повторная отправка той же формы не создаёт вторую заявку (кнопка неактивна до перехода).
- На `/dyakuyemo/?type=lead` — «Дякуємо! Заявка № {id}. Менеджер звʼяжеться з вами протягом [N] хвилин у робочий час» (срок — плейсхолдер, Q-10) и следующие шаги; страницу наполняет SPEC-005, текст для заявок задаёт эта спецификация.

## 5. Доступность
- У каждого поля видимая подпись; обязательность — словом «обовʼязково», не только звёздочкой.
- Ошибки: `aria-invalid`, `aria-describedby` на текст ошибки; сводка ошибок со ссылками на поля, фокус на сводку.
- Группы (тип обʼєкта, що цікавить, месенджер) — `<fieldset>` + `<legend>`.
- `autocomplete`: `name`, `tel`, `address-level2`; `inputmode="tel"`.
- Области касания ≥ 44 px; видимый фокус.

## 6. Мокап → боевой
| Что | В мокапе | В боевом сайте |
|---|---|---|
| Отправка | `console.info` + переход | `POST` на сервер → CRM (KeyCRM / Bitrix24 / HubSpot, выбирает заказчик) |
| Уведомление менеджеру | нет | Telegram-бот (ТЗ §10.1) |
| Антиспам | honeypot + 3 с | + серверная проверка и rate limit |
| Срок ответа менеджера | `[N] хвилин` | из регламента заказчика |
