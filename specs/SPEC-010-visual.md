## 1. Цель
Выбрать и зафиксировать, как выглядит ETS GRID: «спокойно, но с зарядом» (ТЗ §8.1), заметно иначе, чем конкуренты и «вкус по умолчанию» генераторов. Результат — `DESIGN.md` и итоговые значения токенов, по которым доводятся все страницы. Без этого этапа визуальные критерии SPEC-006 (AC-21…23) и визуальные эталоны D-024 не закрываются.

## 2. Источники
- ТЗ §8 целиком (принцип, направления А и Б, фото, иконки, моушн, дизайн-система, таблица референсов 8.7), §11 (шрифты: сабсет, `swap`, ≤ 2 файла на первый экран).
- Концепция студии §2 (образ «світле вікно»), §5 (цвет, шрифт, графика, движение); бриф студии §3.
- `04_FOTO_istochniki.md` — источники, список кадров 1–9, учёт.
- `ets-grid-site/PRODUCT.md` — контекст для `impeccable`.
- Решения: D-009 (`impeccable` — основной инструмент), D-014 (чистый CSS), D-020 (без пресетов taste-skill), D-026 п. 7–8, D-031.

## 3. Порядок раунда
1. **Подготовка (Claude).** `impeccable` в режиме новой работы по PRODUCT.md и ТЗ §8. Два направления — **А «Тёплий світ»** и **Б «Сигнал»** — на одних и тех же экранах: первый экран главной и листинг с карточкой, на 1440 и 375. Для каждого: пара шрифтов, шкала типографики, итоговые цвета обеих поверхностей, форма (радиусы, тени), образец иконок, подход к фото, образец движения «світло вмикається».
2. **Показ (Дмитрий).** Скриншоты 4 экранов × 2 направления — приватная страница-артефакт для сравнения рядом. Выбор направления (и правок к нему) — решение Дмитрия, запись в DECISIONS; закрывает H-010.
3. **Фиксация (Claude).** `impeccable-documenter` пишет `DESIGN.md` по выбранному направлению; значения переносятся в `tokens.css` (имена — без изменений, SPEC-001 §3.6); шрифты — в `public/fonts/`; иконки — компонентами.
4. **Доводка.** Визуальная полировка шаблонов (главная, уровень, листинг, карточка) — отдельными командами по D-032; ревью `impeccable-finish-reviewer`, `design:accessibility-review`; моушн — `design-motion-principles`, агент `motion-reviewer`.

## 4. Что фиксирует направление (содержимое `DESIGN.md`)
| Раздел | Ограничения |
|---|---|
| Цвет | опорные значения ТЗ §8.2 не меняются; остальные — подбираются; все пары «текст / фон» проходят WCAG AA (тест SPEC-001 AC-11 остаётся зелёным); 1 акцент + функциональные статусы |
| Шрифты | 2 семейства (акцидентный + текстовый); полная украинская кириллица (ґ, є, і, ї, ʼ — проверяется на образце текста); веб-лицензия (OFL или купленная); self-host, сабсет, `font-display: swap`, ≤ 2 файла на первый экран; **запрещены** Unbounded, JetBrains Mono и тройка Unbounded / Golos / JetBrains Mono (концепция §5); цифры — `tabular-nums` текстового шрифта |
| Иконки | один линейный набор, обводка 1,5–2 px (ТЗ §8.4): уровни, характеристики (мощность, разъём, фазы, IP, гарантия), услуги; пиктограммы разъёмов Type 2 / CCS2 / GB/T / CHAdeMO — свои, в той же манере; открытая лицензия (MIT / ISC) |
| Фото | ТЗ §8.3: товар на `#F4F6F8` 1:1 или 4:5; объекты 16:9 / 3:2, приглушённые и тёплые; герой — реальное фото станции, без 3D и «человека с ноутбуком» |
| Форма и ритм | радиусы, тени, отступы секций 96–140 / 56–80 px (ТЗ §8.1), чередование светлых и тёмных секций без «зебры» |
| Яркие элементы | только места таблицы ТЗ §8.1: акцентная кнопка, линии энергии, крупные цифры, одна плашка-манифест на страницу, индикаторы-«светодиоды», бегущая строка (не обязательна) |
| Движение | «світло вмикається»: нарастание яркости 300–600 мс, только `transform` и `opacity`, `prefers-reduced-motion` — всё статично; запрещены скроллджекинг, параллакс на каждом блоке, неон, фоновое видео, 3D в первом экране |

## 5. Фото для мокапа (закрывает Q-6)
- Список кадров — `04_FOTO_istochniki.md` §3, кадры 1–6 и 9 (товары на нейтральном фоне).
- Источники мокапа: свободные стоки (Unsplash, Pexels — лицензия проверяется при скачивании) и медиа-разделы производителей; ссылки из `refs/` — только для этапа макетов.
- **Скачивание файлов — только с разрешения Дмитрия** на конкретный список (имя, источник, лицензия); сырые файлы — в `sources/photos/raw/` (вне git), оптимизированные AVIF/WebP — в `public/img/`, каждое — строкой в `public/img/CREDITS.md` с пометкой «макет, заменить» для чужих фото.
- В «Обʼєкти» чужие фото не ставятся никогда (D-005).
- Логотипы брендов на фото — только если бренд есть в каталоге (сейчас бренды — плейсхолдеры, значит фото без читаемых логотипов).

## 7. Критерии приёмки
- [ ] **AC-01** · Два направления показаны на 4 экранах (главная и листинг × 1440 и 375) в одной странице сравнения · вручную
- [ ] **AC-02** · Выбор Дмитрия записан в DECISIONS; H-010 получает запись в журнале · вручную
- [ ] **AC-03** · `DESIGN.md` содержит все разделы §4 и описывает выбранное направление по коду, а не по намерениям · вручную (`impeccable-documenter`)
- [ ] **AC-04** · `tokens.css`: имена токенов не изменились; тест контраста SPEC-001 AC-11 зелёный в обеих палитрах · `unit`
- [ ] **AC-05** · Шрифты: 2 семейства, ≤ 2 файла на первом экране, `font-display: swap`, образец «ґ є і ї ʼ» отображается без подмены · `build`, `functional`
- [ ] **AC-06** · Запрещённые шрифты и цвет `#C8F03C` нигде не встречаются (тест SPEC-001 AC-12) · `build`
- [ ] **AC-07** · Иконки: один набор, обводка 1,5–2 px, у каждой — `aria-hidden` или подпись · `build`
- [ ] **AC-08** · Каждое фото в `public/img/` есть в `CREDITS.md` с источником, лицензией и этапом · `build`
- [ ] **AC-09** · Визуальные эталоны снимаются после утверждения: главная, уровень, листинг, карточка × 375 и 1440 (D-024) · `visual`
- [ ] **AC-10** · Lighthouse mobile ≥ 90 / 95 / 100 на главной, уровне, листинге, карточке после доводки (отчёты в `qa/`) · вручную
